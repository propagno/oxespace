# Thread failure diagnostics

Implemented on 2026-09-18. Provider failures now retain a bounded, credential-redacted diagnostic with occurrence time, provider error identifier and HTTP status when supplied. Authentication, exhausted usage, request throttling, context, session budget, sandbox, configuration, network and provider server failures have distinct explanations.

Codex publishes an immediate failed completion. A single shared, eight-second `account/rateLimits/read` request enriches that completion by its failure ID; it cannot change a later turn's status or append extra transcript messages. Global rolling usage updates preserve missing/null snapshot fields. Failed/disposed connections cannot leave an indefinite usage-loading indication. Session, weekly and individual/workspace spending windows use the actual supplied percentages and reset timestamps, converting native UNIX seconds to milliseconds once. The interface displays dates, local timezone and the snapshot's check time. A current usage snapshot does not prove that usage caused an unrelated failure.

The newest failure opens by default and can be collapsed. Refresh usage and `/usage` stay in the conversation interface. Claude retains its stream result/authentication diagnostics; this transport does not provide account usage windows, so the interface does not invent a reset. Old saved generic failures remain readable but their historical cause cannot be recovered.

Validation covers classification, credential removal, incomplete windows, local reset display, refresh failure, rolling updates, retry recovery, failure-ID persistence, and isolation from later turns/projects. Electron UI verification includes a quota-failure fixture at 900 and 1280 pixels, refresh, collapse and absence of CLI tools.

Verified: 100 Thread/conversation unit and integration tests passed; seven additional tests passed against installed native CLI protocols, including real account usage reads without inference. Electron E2E, TypeScript and targeted ESLint passed. Production build and all bundle budgets passed (main 902/904 kB, renderer 493/500 kB). Preload forwards the existing command/snapshot API. `failure-details` is consumed and merged in the manager rather than appended to stored events. Existing timeline, grouping, model-picker, native history, RPC/account and command consumers were inspected; TypeScript and the broad Thread suite confirm compatibility. Old generic snapshots remain supported by the card.
