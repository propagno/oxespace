# Accessibility scan with axe

Since 1.4 the scan is a gate: `.github/workflows/a11y-axe.yml` runs on every pull request to `main` with
`OXE_A11Y_STRICT=1` and fails on any critical or serious finding. Moderate and minor findings, and surfaces
it could not reach, stay in the uploaded report. Run locally without the variable, it only records what it
finds. The manual screen-reader pass is in `screen-reader-1.4.md`.

- **Tool:** `@axe-core/playwright` 4.13.0 (axe-core 4.13.0), WCAG 2.0 and 2.1, levels A and AA.
- **Run:** `npm run test:a11y` (spec `e2e/visual/a11y-surfaces.spec.ts`), Windows, built app, light and dark.
- **Report:** `<tmp>/oxespace-a11y-report.jsonl`, or the file named by `OXE_A11Y_REPORT`. Set
  `OXE_A11Y_STEPS=<file>` to log when each scan starts and ends: a clean surface writes nothing to the report,
  so without it a test that stalls cannot be told apart from one that found nothing.

## What is scanned

Code: empty screen, new-workspace wizard, workspace, Tools menu, command palette, Changes (diff), Classic
review, GitHub, Find in Files, Editor with a file open, Web Preview, and the Settings center (the page it opens
on, Application and Repo, and one entry each of Appearance, Terminal, Project memory and Agent delegation; see
below for the entries that could not be opened). OxeQuery: the view, the containers screen and the
connection dialog. Thread: empty, conversation, approval, question, usage failure, review panel.

Excluded on purpose: terminals (`.xterm`, canvas) and Monaco (`.monaco-editor`, which has its own
screen-reader mode). axe runs in legacy mode (main frame only), because the default mode needs
`context.newPage()`, which Electron does not support; the preview webviews are third-party content.

## What is not scanned, and why a clean result there means nothing

- **Settings pages that could not be opened.** Five entries in the Settings center navigation did not accept
  a click within 10 s in the scripted state, in both themes: Appearance, Terminal, Project memory, Agent
  delegation and an eleventh entry. They are recorded as `scan-not-reached`, not as clean. The cause is in
  the scan, not in the app, found by reading `SettingsCenter.tsx` and its CSS: the selector also matched the
  scope buttons, "Back to work" and a compact copy of the category list that is `display: none` at this width,
  and clicking a scope button rewrites the list of pages, so positions read earlier pointed elsewhere. The
  spec now uses only the visible "Settings categories" navigation and re-reads it after each scope change.
  That change has been type-checked and linted but **not yet run**, so the five entries remain unscanned until
  the next run.
- **The app runs in the E2E mock mode** (`OXESPACE_E2E_MOCK_NATIVE=1`) for determinism, so OxeQuery and the
  other data surfaces show the mocked, empty state. A clean result on the OxeQuery view says nothing about its
  tables, editors, result grids or import and export dialogs, which were not opened.
- **Not opened at all:** Teams, Delegation, Linear, Scripts, Background jobs, Worktrees, MCP, Skills, Semantic,
  Documentation, the workspace-scoped panels other than those listed, and any state that needs real agents or a
  provider.
- axe cannot judge reading order, focus order, or whether labels make sense, and no screen-reader pass (NVDA)
  was done, so no conformance claim can be made from this scan.
