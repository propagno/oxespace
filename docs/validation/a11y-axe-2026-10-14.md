# Accessibility scan with axe, 2026-10-14

Informative for 1.0: the scan records findings and does not fail the build. Set
`OXE_A11Y_STRICT=1` to make it fail.

- **Tool:** `@axe-core/playwright` 4.13.0 (axe-core 4.13.0), WCAG 2.0 and 2.1, levels A and AA.
- **Run:** `npm run test:a11y` (spec `e2e/visual/a11y-surfaces.spec.ts`), Windows, built app, light and dark.
- **Report:** `test-results/a11y-report.jsonl`, or the file named by `OXE_A11Y_REPORT`.
- **Result:** 12 records on 11 surfaces: 4 rules, 44 failing elements. 4 of 4 tests ran; they do not
  fail in informative mode.

## What is scanned

Code: empty screen, new-workspace wizard, workspace, Tools menu, command palette, Changes (diff),
GitHub. Thread: empty, conversation, approval, question, usage failure, review panel. Each in light and dark.

Excluded on purpose: terminals (`.xterm`, canvas) and Monaco (`.monaco-editor`, which has its own
screen-reader mode). axe runs in legacy mode (main frame only), because the default mode needs
`context.newPage()`, which Electron does not support; the preview webviews are third-party content.

## What is not scanned

Settings, OxeQuery, Review ("Classic"), the editor and file browser, Find in Files, Web Preview, the
other Tools panels, and any state that needs real agents or a real provider. A clean result here
therefore says nothing about those surfaces. axe also cannot judge reading order, focus order, or
whether labels make sense; it was not complemented by a screen-reader pass (NVDA), so no
conformance claim can be made from it.

## Findings

| Rule | Impact | Elements | Where | Likely cause |
|---|---|---|---|---|
| `aria-required-parent` | critical | 32 (16 per theme) | Tools menu | The Tools hub items (`button[aria-label="Team"]`, `"Multi-repo coordination"`, `"GitHub"`, …) carry `role="menuitem"`, but no ancestor is a `menu`, `menubar` or `group`. |
| `nested-interactive` | serious | 6 | Workspace, Changes, GitHub (both themes) | `.ws-group-header` in the Code sidebar nests an interactive control inside another one. |
| `color-contrast` | serious | 4 | **Light theme only**: Changes tree (`.is-A > .changes-tree-name`, the colour for an added file) and Thread file stats (`.thread-file-stats > span`, the green `+N`) | Added-file and addition colours do not reach 4.5:1 on the light surface. |
| `aria-prohibited-attr` | serious | 2 | Thread, empty state (both themes) | `.thread-timeline` has an ARIA attribute its role does not allow. |

No violations were found on the empty screen, the new-workspace wizard, the command palette, or the
Thread approval, question, usage-failure and conversation states.

## Who owns what

These are design and Thread components that other sessions are editing, and 1.0 is under a feature
freeze, so they were not changed here. Suggested order if they are taken on: the Tools menu parent
role (critical, one place), then the sidebar group header, then the light-theme colours, then the
`.thread-timeline` attribute.
