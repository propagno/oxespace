# OXESpace 0.16.0-beta.3

This beta fixes a regression in long Codex conversations introduced by the Thread app-server integration. In beta.2, resuming a large native session could ask Codex to return every previous turn in one protocol response. OXESpace capped each response at 1 MiB, so the connection failed with `Agent protocol message exceeds size limit` before a new answer appeared.

- Thread now resumes Codex sessions without requesting their full native turn history. The existing bounded local history remains available in the conversation.
- Live Codex protocol events can be larger when needed, with a finite 32 MiB per-message ceiling. Thread still retains only bounded command output in its event history.
- Regression tests cover a large live command event and the history-free resume request.

The release remains on the beta channel. The limits documented for beta.2 still apply: remote OAuth connectors, the unified cross-source Activity action model and the single Tools action registry are incomplete. Windows installer side effects still need validation in an isolated VM.
