# OXESpace 1.0.1

A fix release for 1.0.0. The most important change: **OxeQuery connects again on installed
builds**. Installs of 1.0.0 on Windows update automatically; on Linux, install the new
package.

## Fixed

- **OxeQuery could not open any connection on installed 1.0.0 builds** (PostgreSQL and
  MongoDB alike): the database worker stopped with "Cannot find package 'pg-cloudflare'".
  The worker no longer needs that package, and the release checks now run the packaged app
  outside the source tree and refuse a build whose bundles import a package the installer
  does not ship.
- **Rename** works while a conversation is still running or waiting on background work, and
  the rename, archive, delete, rewind and checkpoint dialogs have real buttons, with Cancel
  and one clear action.
- **Scrolling up** from the end of a conversation no longer shakes between two positions.
- **The conversation list** keeps a stable order while agents work: conversations by
  creation, newest first; projects by name.
- **Answering a question with your own text** ("Other answer", or several choices) no longer
  makes Claude ask the same question again.
- **Long messages**: Thread accepts up to 1,000,000 characters (was 65,536) and says when a
  message is over the limit.
- **Background shell commands** no longer appear as cards inside the reply; they stay in the
  Background activity panel.
- **Settings › Voice** says why voice input is unavailable on Linux, and select boxes no
  longer cut their text.
- **Team**: Add member and Send to inbox are normal buttons.
- **RTK update check** gives up after 15 seconds instead of showing "Checking" forever.
- **OxeQuery** says when the container engine refused access (for example, your user is not
  in the `docker` group).

## Improved

- **Connections** opens on *This conversation*: every MCP server the conversation's session
  loaded, from OXESpace, your provider settings, the project's `.mcp.json` and claude.ai
  connectors, grouped as connected, needs sign-in and failed.
- **The MCP chip** in the composer counts connected servers and warns only when a server you
  configured failed; claude.ai connectors waiting for a sign-in are not counted as failures.
- **Narrow sidebars** show the provider icon instead of a cut name, and archived
  conversations take one line.

## Known limits

The limits listed in [1.0.0](1.0.0.md) still apply.
