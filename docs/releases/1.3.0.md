# OXESpace 1.3.0

MCP servers your agents connect to themselves, a starting point for new conversations, and a
consistent finish across the app. Installs of 1.2.x on Windows update automatically; on Linux,
install the new package (the AppImage updates itself).

## MCP servers

- **Agents own the connection.** Remote connectors go to the agent as native HTTP (or SSE)
  servers, so the agent signs in itself on first use; there is no `mcp-remote` bridge in between.
  Servers you saved as a bare `npx -y mcp-remote <url>` become the remote server they bridged.
- **Test instead of Start/Stop.** OXESpace no longer keeps a second copy of each server running.
  **Test** runs the handshake, lists the tools and lets the server go. A remote server that asks
  for a sign-in shows as such, not as broken. Each installed server also shows whether the agent
  of the open conversation connected to it, and the top bar counts the servers "for agents".
- **GitHub** uses its own server, with a personal access token.
- **Codex in a Code terminal** receives the OXESpace servers, with secrets in its environment.
  `~/.codex/config.toml` is not touched.
- **The catalog follows the providers.** Linear and Cloudflare move to their current endpoints
  (servers you already saved are updated at boot); GitLab and Figma use their official remote
  servers, and Figma no longer needs the desktop app; PostgreSQL, Brave Search and Slack move to
  maintained packages. Dropbox and Google Maps are gone from the catalog, since their packages no
  longer exist or are no longer supported. The PostgreSQL server can write: give it a read-only
  role.

## Conversations

- **An empty conversation is a starting point.** It names the agent and project, shows where it
  works (folder, branch, access, model) and offers four starters that fill the composer. Nothing is
  sent until you send it.
- **Status is said once.** The account notice shows only when there is something to do, not while
  a check is running or merely could not confirm the account. "Waiting for your input" no longer
  repeats the request card on screen, and a sign-in failure is handled in one place.
- **The conversation no longer shakes**, neither while you type nor around the final answer, and
  the message box grows with its text.
- Thread buttons share one shape.

## OxeQuery

- **A host pasted as a URL works**, for example `postgres://db.example.com:5432`.
- **New PostgreSQL connections use TLS when the server offers it**, and connect without it only
  when the server has none (libpq's `prefer`), so managed databases such as Amazon RDS connect out
  of the box. Saved connections keep their mode.

## Finish

- **Errors read as sentences.** Every error the app shows goes through one place: missing files,
  busy or full disks, network failures, timeouts and sign-in errors say what happened, instead of a
  raw stack line.
- **Loading looks the same everywhere**, instead of a loose "Loading…" line.
- **One name per thing.** "MCP servers" are MCP servers (the top bar's button is **MCP**);
  "Connections" means only OxeQuery's database connections. "Background activity", "Integrations"
  and the **Browser** panel use one name everywhere, and titles are in sentence case.
- **Narrow panes stay readable.** In a narrow pane the branch badge steps aside and the agent chip
  keeps only its icon, so the pane name is never cut to a few letters. Side panel tabs show their
  icon, with the name in the tooltip.
- **GitHub panel** actions are standard buttons and fill the panel's width.
- **OxeQuery:** the Mongo Filter, Projection and Sort boxes line up, and the SQL row detail leaves
  the result grid room for its columns in a narrow window.
- Styles moved to the design tokens and a single layering scale, so menus, popups and notices stack
  the same way in every mode.

## Known limits

- An agent signs in to a remote MCP server on first use, so the first call to a new server may ask
  you to sign in.
- If you signed in to a connector through `mcp-remote`, sign in again, now through the agent (in
  Claude Code, `/mcp`).
- A Codex started in a Code terminal may need `codex mcp login <name>` before it can use a remote
  server that asks for a sign-in.
- GitHub's MCP server needs a personal access token. A GitHub server you saved before keeps working
  on the old package; add it again from the catalog to use GitHub's own server.
- The limits listed in [1.2.0](1.2.0.md) still apply.
