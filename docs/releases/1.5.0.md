# OXESpace 1.5.0

OXESpace is now three places: **OxeCode** (terminals and agents in your project), **OxeChat** (conversations with
Claude Code, Codex and Antigravity) and **OxeQuery** (your databases). Around them, 1.5 lets you see what your agents
do, decide what they may do, and undo it. Several features left to make room; their data was saved first.

Installs of 1.4.3 on Windows update automatically; on Linux, install the new package (the AppImage updates itself).

## See what your agents do

- **Agent activity.** Settings › Agent activity is one list of what your agents changed, queried, called and started:
  files, databases, containers and HTTP calls, with a filter for each source.
- **HTTP calls.** Every HTTP call your agents made from a terminal, with secrets masked. It's a panel in OxeCode and
  the Network tab of a conversation.
- **Agent browser.** Watch the agent drive your app, at desktop or phone size.
  - Click an element of the page and the agent gets the file and line it was written in (React, Vue, Svelte, Astro;
    in React 19 and Svelte the line is approximate, and the panel says so).
  - **Dev servers** reads `.claude/launch.json` and the scripts of `package.json`: it starts and stops them and opens
    the page at the address the server reports.
  - The errors the page wrote to its console go to the agent in one click. With agent access on, **Auto-verify** tells
    the agent where the page is and how to check its own change.
- **Containers** has its own panel in OxeCode.
- **Android** has a panel with the device or emulator's screen.
  **Install an APK…**, **Open a link…** and, with the OXESpace development app on the device, **Pair this device
  with OXESpace** over the cable.
  These are your actions: no agent installs an app, opens a link or pairs, and each one is recorded.
- **Usage.** The usage meter follows `CLAUDE_CONFIG_DIR` and `CODEX_HOME`. It shows Antigravity beside
  Claude and Codex (5-hour window, weekly window and plan), on Windows only in this version.

## Decide what they may do

- **Approvals show their impact.** A request names the action and shows the command or the lines it changes. A step
  that can't be undone has to be held to approve. Everything waiting for you is in one queue (`Ctrl+Shift+A`), and
  the top bar says how many.
- **Access per conversation**: Read only, Can edit or Full access, from the chip in the message box.
- **New conversations start with Full access, and so do agents started in OxeCode terminals.** Both are settings:
  Settings › Agents › *Access a new conversation starts with*, and Settings › Terminal › *Start agents without
  permission prompts*. Conversations you already have keep their access. With Full access the agent runs commands and
  edits files without asking; rules you saved to deny, plan approvals and questions still reach you. **If you want to
  be asked, change both settings after updating.**
- **Command bar** (`Ctrl+K`): ask an agent, run a command or go anywhere in the app.
- **Outgoing hosts** (off by default): a local proxy that lists the hosts each conversation reached. It records host
  and port only, never content.
- **Usage count** (off by default) is kept on your computer.

## OxeChat

- **Antigravity** is a third agent beside Claude Code and Codex: new and resumed sessions, thoughts, answers, tools,
  plans, approvals, images and Google sign-in. What its protocol doesn't offer is shown as unavailable.
- **One line says what the conversation is doing**: "Working. Editing src/app.ts.", "Claude asks you to review its
  plan.", "Paused.", with the action that fits beside it.
- **Where the conversation worked.** Changes are grouped by place (the project or a worktree), against the state each
  place had when the conversation first touched it. Undo a file or one block, restore it, or discard a place. A
  conversation can start in a branch and worktree of its own.
- **Pull request tab**, for GitHub and Azure DevOps, and a **Worktrees** panel that says who owns each one and whether
  it's merged.
- **Reading a conversation.** A turn is closed once, under the answer. The latest turn opens its first changed file by
  itself. The title is the first sentence, not the first 80 characters. The list says Working, Finished and Paused.
- **Plan mode.** The plan to approve is shown as prose; approving it leaves plan mode; with Read only, a line says
  what it takes to run the plan.
- **Closing or quitting with a turn in progress asks first.**
- Stop works at the first click in a conversation reopened after the app closed mid-turn.
- Code blocks have colour and the name of their language. Right-click offers Cut, Copy, Paste and Select all in
  fields, and Copy and Quote on selected text. Images in an answer are drawn when they come in the answer or are an
  image file of the project; nothing is fetched from the network. The list's filter shows the passage that matched.
- **Formulas (LaTeX) and diagrams (Mermaid)** are drawn in the answer; a diagram has **Show code** and **Copy**.
- **Schedules.** A request sent to an agent at a set time: once, on days at an hour, or every few hours. Each run
  opens a conversation with the schedule's name, with Read only or Can edit access. A button on each schedule runs
  it now; there's a history of runs, and you can pause one or all; three failures in a row pause a schedule. It runs only while OXESpace is open.

## OxeCode

- **Each terminal says what it's doing in plain words**: a shell with no agent reads "Idle" after a command and
  "Running" while text comes out. The pane's title is "Terminal N" or the name you gave it.
- **Splitting a pane from its menu shares the space the pane had**, without widening its neighbour. The grid chip
  shows the grid the panes form ("2 × 2", "1 × 3") or "Custom".
- **Sidebars collapse to a rail**, and each workspace has a colour.
- **Menus.** Edit acts where the cursor was. An item that can't run says why instead of being grey without a word.
- "Stop terminal" shows in the pane ("Exited", with **Start Terminal**). "N agents working" counts agents, not shells.
  The Containers panel says when it's loading and when it couldn't read.

## OxeQuery

- **Run** shows its shortcut (`Ctrl+Enter`), the time limit reads "Timeout 60 s", and agent access reads "Agents: off",
  "Agents: read only" or "Agents: read and write".
- A connection shows when agents used it, with a way to that activity.

## On your phone

- **The request to pair appears anywhere in the app**, not only with Settings › Devices open.
- **A pairing that wasn't used in time says so**, instead of reading as removed.
- **You choose which terminals the phone sees.**
- Settings shows the paired computer (name, state, address, unpair with confirmation), the terminal's text size and
  About. The terminal is dark in both themes, and the local network notice is readable and clear of the camera.

## What left OXESpace, and where it went

The first time 1.5 opens it saves what these features held (memories, automations, and the OxePost requests of your
open workspaces) to a file, and **What changed in 1.5** shows where it is. Secrets aren't in the file. You can save it
again from Settings › Data.

| Left | Use instead |
|---|---|
| OxePost | The HTTP calls panel |
| OxePod | The Containers panel |
| AI Memory, Search by meaning | The agents' own memory and search |
| Automations | Schedules in OxeChat (once, on days at an hour, or every few hours). For cron and a check before each run, `/loop` and the agent's own scheduled routines |
| Teams | Delegated work |
| Linear, CodeGraph | Their own MCP servers |
| RTK | Install RTK yourself |
| Documentation tools | Agents write docs in the repository |
| File editing inside OXESpace | Open in editor |
| Skills manager | A read-only list; run a skill with `/` |
| Rewind, History and "Edit" on a sent message | Undo on a turn's changes; "Retry the failed step" |
| Scripts panel | Run scripts in a terminal; the Dev servers menu of the Browser panel |
| Fork, for Claude conversations | Still offered for Codex |

**Automations from 1.4.3 aren't carried over.** They're in the saved file; create the ones you still want as
schedules.

A conversation left by an earlier version with a rewind not yet confirmed is put back whole when the app opens; no
file is touched.

## Verify the Android APK

Before installing `oxespace-android-v1.5.0.apk`, check that it's the published file and that the project's key
signed it:

1. `sha256sum -c oxespace-android-v1.5.0.apk.sha256` (both files are in this release's assets).
   On Windows: `Get-FileHash oxespace-android-v1.5.0.apk` in PowerShell, and compare it with the value in the
   `.sha256` file.
2. `apksigner verify --print-certs oxespace-android-v1.5.0.apk` (Android SDK build-tools). The line
   `Signer #1 certificate SHA-256 digest:` must read `cc65d90afa2fde6518adad92d40769496a043b901f603eff0562e056cd4336e4`.

The signing certificate's SHA-256 fingerprint is:

`CC:65:D9:0A:FA:2F:DE:65:18:AD:AD:92:D4:07:69:49:6A:04:3B:90:1F:60:3E:FF:05:62:E0:56:CD:43:36:E4`

It's the same key as 1.4.3, so the app updates in place. The full steps are in
[Verifying an APK before installing it](https://github.com/propagno/oxespace/blob/main/mobile/android/RELEASING.md#verifying-an-apk-before-installing-it).

## Known limits

- **Not checked on a device.** The phone changes of this version were checked by the Android CI (lint, screenshots,
  protocol tests), not on a phone or an emulator. The Android panel's three actions were exercised
  against a simulated `adb`.
- **Not started with a real agent.** The option that starts terminal agents without permission prompts was read from
  each agent's own help and covered by tests; for Codex resuming a session it wasn't observed.
- **Schedules** were run once with Claude in Read only; Can edit, Codex, Antigravity and a missed run weren't.
- **Antigravity usage** has no reading on macOS or Linux.
- **A formula in the status line** shows its source, not the drawing.
- **OxeQuery** was checked against the simulator, not a real database, in the last round.
- **Visual details are still open** and come in 1.5.1: two Stop buttons while an agent works, chips that get squeezed
  in a narrow message box, widths that differ inside a conversation, a tooltip with the version over the OxeCode
  sidebar.
- After a restore, the conversation list can still show the turn as finished.
- Settings differs from its design in the General, Appearance and Approvals pages.
- The final check of this exact build as an installed app was done by the release workflows, not by hand.
- **The cost of OXESpace's MCP tools was not measured again for this version.** The last measurement, with the
  versions of Claude Code and Codex of 1.4, is in `docs/validation/tool-groups-cost-1.4.md`. If a newer agent sends
  every tool definition up front, a conversation can use more context than that page says.
