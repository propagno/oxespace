# OXESpace 1.4.3

Phone pairing that works on a real network, and a phone terminal that shows what's already on screen. Installs of 1.4.2
on Windows update automatically; on Linux, install the new package (the AppImage updates itself).

## Pairing your phone

- **Settings › Devices says when Windows keeps phones out, and fixes it.** It names the one problem in the way:
  - a Public network, with the steps to set your Wi-Fi to Private (OXESpace doesn't change it for you);
  - no firewall rule for phones yet, with **Allow on private networks**. That adds one Windows Firewall rule for
    OXESpace.exe, on the pairing port, Private networks only. Windows asks for permission first, and you can remove the
    rule from the same place;
  - a Block rule that wins over any Allow, which OXESpace never removes for you.
- **A phone paired just now connects right away**, instead of being shown as removed a couple of minutes later.
- **The phone checks the connection before it shows "Paired".** It signs in once with the new pairing; if that fails,
  it tells you why and keeps nothing.
- **Back in the foreground, the phone reconnects at once** instead of waiting out up to a minute.

## The terminal on your phone

- **Opening a terminal shows its current screen**, not a blank view until new output arrives.
- **Full-screen terminal apps read right**, because the phone keeps a real terminal screen.
- **A conversation opens at its latest message**, with a **Latest ↓** button when you scroll up.

## Verify the Android APK

Before installing `oxespace-android-v1.4.3.apk`, check that it's the published file and that the project's key
signed it:

1. `sha256sum -c oxespace-android-v1.4.3.apk.sha256` (both files are in this release's assets).
   On Windows: `Get-FileHash oxespace-android-v1.4.3.apk` in PowerShell, and compare it with the value in the
   `.sha256` file.
2. `apksigner verify --print-certs oxespace-android-v1.4.3.apk` (Android SDK build-tools). The line
   `Signer #1 certificate SHA-256 digest:` must read `cc65d90afa2fde6518adad92d40769496a043b901f603eff0562e056cd4336e4`.

The signing certificate's SHA-256 fingerprint is:

`CC:65:D9:0A:FA:2F:DE:65:18:AD:AD:92:D4:07:69:49:6A:04:3B:90:1F:60:3E:FF:05:62:E0:56:CD:43:36:E4`

It's the same key as 1.4.2, so the app updates in place. The full steps are in
[Verifying an APK before installing it](https://github.com/propagno/oxespace/blob/main/mobile/android/RELEASING.md#verifying-an-apk-before-installing-it).

## Known limits

- **The computer asks "Pair <phone>?" only while Settings › Devices is open.** Open it before scanning the code. In
  1.5.0 the request appears anywhere in the app.
- **A pairing that isn't used within its time limit still reads as removed** on the phone. Pair again; the clearer
  message comes in 1.5.0.
- The limits listed in [1.4.1](https://github.com/propagno/oxespace/releases/tag/v1.4.1) still apply.
