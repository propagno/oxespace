# OXESpace 0.16.0-beta.7

This prerelease makes stalled Thread input actionable and adds a bounded path for agents to exercise Web Preview and hand an image directory to a new normal Thread.

- Pending MCP questions and approvals stay visible above the Thread composer even when their original events have left the loaded history. An approval state without a request offers refresh and diagnostics; long silence is identified instead of presenting an endless unexplained input wait.
- Long commands and diffs remain inside the conversation. The elapsed timer identifies the whole turn, and Full access now displays the separate command approval policy and explains MCP confirmations.
- Internal MCP discovery no longer waits for delegation project checks. Bridge calls have absolute deadlines and correlation IDs; slow or disconnected calls produce small, argument-free diagnostic entries in the rotating main log.
- `oxespace_open_web_preview` reports a queued navigation and directs the agent to confirm the active URL. `oxespace_capture_web_preview` can save a redacted PNG under the OXESpace capture directory with an absolute directory and file path.
- A live Thread can use `oxespace_thread_create` and `oxespace_thread_send` to start a normal Thread in the same project and send a text message. Stable keys prevent duplicate creation or automatic repeat of an uncertain send.
- Filesystem and database recovery safeguards and the dependency/runtime updates from the local stabilization cycle are included. The database migrates to schema 63 and retains a bounded pre-migration backup.

## Testing and limits

Focused MCP, migration, Thread and preview checks passed locally. Playwright exercised the real Electron Web Preview and verified a saved capture. The release workflow additionally builds and verifies Windows and Linux artifacts before publishing.

Playwright automation in the release check controls the Electron application. Agent-side Web Preview interaction remains available through `oxespace_preview_interact`; this beta does not expose the Electron webview as a general Playwright browser endpoint. The exact layer responsible for the original long MCP stall was not identifiable from the old installation's logs. The new deadlines and correlation entries allow a repeat to identify it without leaving a call pending indefinitely. MCP confirmations still require explicit user response when the provider requests them.

No local Docker run is required for this release.
