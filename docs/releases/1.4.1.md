# OXESpace 1.4.1

Fixes from the first days of 1.4.0, the Android app's first signed release, and fewer interruptions: OXESpace's own
read-only lookups no longer ask for approval each time. Installs of 1.4.0 on Windows update automatically; on Linux,
install the new package (the AppImage updates itself).

## OxeChat

- **Your messages are back on the right**, and **Stop is always visible** while a turn runs.
- **The model shows its real name** instead of "default". **Effort and permissions show in the message box**, with
  permissions colored by risk. The MCP strip is no longer in the message box.
- **Conversation details scrolls to the end.**
- **A file path in a reply opens from the conversation's own folder**, so files in a worktree or another folder open
  instead of showing "does not exist".
- **The side chat stays open when you switch tabs or modes.** ✕ only hides it, and **Discard and close…** asks before
  discarding.
- **The side chat answers your question directly** instead of drawing up a plan, and still can't change anything.
- **The collapsed sidebar** in OxeChat, OxeQuery and OxePod **shows your conversations, connections and containers**,
  and expanding it keeps what was open.

## Approvals and terminals

- **OXESpace's read-only lookups join "Auto-approve reads".** Code search, callers, impact and the other read-only
  lookups of the project no longer ask on each use, so the 1.4.0 known limit is gone. Lookups that reach beyond the
  project (GitHub, Linear, automations, settings, usage, team and delegation) still ask.
- **A resumed Claude Code session comes back in the permission mode it started in.** Skipping permissions comes back
  only when you turn on the new setting in **Settings › Terminal**, which is off by default.
- **A message sent while OXESpace's tools are still starting waits for them** instead of failing with "Could not run
  thread agent".
- **A long command can be read in full before you approve it**, and **Copy exact text** is always visible.

## OxePost, OxeQuery and the rest

- **OxePost: "New request" creates the request and opens it.** Failures are shown, and the palette asks before
  discarding changes.
- **OxeQuery: clicking a query in Agent activity opens it in full**, with **Copy** and **Open in editor**.
- **Usage names each account after its provider**: a Codex account no longer shows as "Claude account".
- **The path menu opens with your editors already listed** and keeps them in place, so a quick click on **Copy relative
  path** no longer opens an editor instead.
- **A faster first click after startup**, and a smaller interface to load.
- **Dialogs open with the cursor in their first field**, or on their first button when they have no field.
- **Consistent names and menus**: "New connection" and "Skills" everywhere, Cancel in dialog footers, a separator
  before destructive menu items, and a short explanation for RTK, Caveman and Semantic in the terminal menu.
  **Keyboard shortcuts show Reset only for a shortcut you changed.**

## Security

- **A conversation OXESpace can't verify is refused when it calls an OXESpace tool**, instead of the call running
  against the active project.

## Your phone

- **Get the Android app from this release's assets**: `oxespace-android-v1.4.1.apk`, signed, with its SHA-256 beside
  it. It's the app's first signed release; 1.4.0 shipped without it.

## Verify the Android APK

Before installing `oxespace-android-v1.4.1.apk`, check that it's the published file and that the project's key
signed it:

1. `sha256sum -c oxespace-android-v1.4.1.apk.sha256` (both files are in this release's assets).
   On Windows: `Get-FileHash oxespace-android-v1.4.1.apk` in PowerShell, and compare it with the value in the
   `.sha256` file.
2. `apksigner verify --print-certs oxespace-android-v1.4.1.apk` (Android SDK build-tools). The line
   `Signer #1 certificate SHA-256 digest:` must read `cc65d90afa2fde6518adad92d40769496a043b901f603eff0562e056cd4336e4`.

The signing certificate's SHA-256 fingerprint is:

`CC:65:D9:0A:FA:2F:DE:65:18:AD:AD:92:D4:07:69:49:6A:04:3B:90:1F:60:3E:FF:05:62:E0:56:CD:43:36:E4`

Every later APK is signed with the same key, and Android refuses an update signed by any other. The full steps are in
[Verifying an APK before installing it](https://github.com/propagno/oxespace/blob/main/mobile/android/RELEASING.md#verifying-an-apk-before-installing-it).

## Known limits

- The limits listed in [1.4.0](1.4.0.md) still apply, except the one about OXESpace's lookup tools asking on each use,
  which this release fixes.
- **The Windows installer is not code-signed yet**, so Windows SmartScreen may warn before it runs.
- **Going back to 1.4.0 needs the automatic backup.** 1.4.1 updates your data the first time it opens, after saving a
  verified copy. 1.4.0 refuses the updated data and says it was created by a newer version; nothing is lost, and
  reinstalling 1.4.1 opens everything again. To go back for good: close OXESpace, install 1.4.0 from the Releases page,
  and **before opening it**, put the newest `oxespace-v90-…sqlite3` from the `db-backups` folder in place of
  `oxespace.sqlite3` (`%APPDATA%\OXESpace` on Windows, `~/.config/oxespace` on Linux). What you did in 1.4.1 after
  updating is not in that copy.
