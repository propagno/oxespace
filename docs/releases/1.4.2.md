# OXESpace 1.4.2

Pairing fixes for the Android app. This release changes only the phone app; the desktop app is the same as 1.4.1, and
installs of 1.4.1 on Windows update automatically.

## Your phone

- **A phone paired just now connects right away.** Before, pairing succeeded but the app went back to the welcome
  screen and never connected until it was force-stopped. Your pairing is kept; nothing needs to be paired again.
- **The code appears only once your computer has the request.** While it reaches the computer, the phone shows
  "Contacting <computer>…". If the computer can't be reached, the phone says so and names the usual Windows cause: on
  a Public Wi-Fi, the firewall blocks the phone.
- **Android 17 asks for local network access.** The app asks for it before scanning the QR code and before connecting,
  explains that it only talks to your paired computer, and opens the app's settings if the permission was refused.
- **A failed connection says why** (refused by the computer, timed out, blocked by the local network setting) instead
  of a generic error.

## Verify the Android APK

Before installing `oxespace-android-v1.4.2.apk`, check that it's the published file and that the project's key
signed it:

1. `sha256sum -c oxespace-android-v1.4.2.apk.sha256` (both files are in this release's assets).
   On Windows: `Get-FileHash oxespace-android-v1.4.2.apk` in PowerShell, and compare it with the value in the
   `.sha256` file.
2. `apksigner verify --print-certs oxespace-android-v1.4.2.apk` (Android SDK build-tools). The line
   `Signer #1 certificate SHA-256 digest:` must read `cc65d90afa2fde6518adad92d40769496a043b901f603eff0562e056cd4336e4`.

The signing certificate's SHA-256 fingerprint is:

`CC:65:D9:0A:FA:2F:DE:65:18:AD:AD:92:D4:07:69:49:6A:04:3B:90:1F:60:3E:FF:05:62:E0:56:CD:43:36:E4`

It's the same key as 1.4.1, so the app updates in place. The full steps are in
[Verifying an APK before installing it](https://github.com/propagno/oxespace/blob/main/mobile/android/RELEASING.md#verifying-an-apk-before-installing-it).

## Known limits

- **On Windows, set your Wi-Fi to Private and allow OXESpace through the firewall** before pairing. On a Public
  network, Windows Firewall blocks the phone. The desktop app will detect this and tell you in 1.5.0.
- **The computer asks "Pair <phone>?" only while Settings › Devices is open.** Open it before scanning the code. In
  1.5.0 the request appears anywhere in the app.
- The limits listed in [1.4.1](https://github.com/propagno/oxespace/releases/tag/v1.4.1) still apply.
