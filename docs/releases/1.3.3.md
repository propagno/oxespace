# OXESpace 1.3.3

Conversations use far fewer tokens. Installs of 1.3.x on Windows update automatically; on Linux,
install the new package (the AppImage updates itself).

## Fewer tokens in every conversation

Every OXESpace tool a conversation can call has a definition that is sent to the model with each
request. Until now every conversation received all 63 of them, about 9,000 tokens per request.

- **A conversation gets only the core tools**: code search and the code graph, semantic search,
  project context and memory. That is 12 tools and about 1,700 tokens per request, 81% less.
- **Roles add what they need.** A team member's conversation also gets the team tools, and one that
  runs a delegation or an Agent Work task, or supervises a Work run, gets the tools to report back.
- **Other groups are turned on per project** in `oxe.yaml`:

  ```yaml
  thread:
    tools: [orchestration, data, docs]
  ```

  `orchestration` starts other agents and conversations, `data` reaches databases and containers
  through OxeQuery, and `docs` covers web previews and documentation captures. The change applies to
  conversations started afterwards. `oxespace_capabilities` tells the agent how to turn them on.
- **Claude loads tool definitions only when it needs them.** OXESpace turns on Claude Code's tool
  search (`ENABLE_TOOL_SEARCH=auto:5`), which also covers your own MCP servers. A value you set
  yourself is kept.
- **Files mentioned with `@` attach their first 16 KB**, up to 48 KB per message (it was 64 KB and
  256 KB). The agent is told to read the rest of a longer file with its own tools.
- **Team messages arrive together.** Messages waiting for a member are delivered in one turn, up to
  ten at a time, instead of one turn each.

## Known limits

- The limits listed in [1.3.0](1.3.0.md) still apply.
