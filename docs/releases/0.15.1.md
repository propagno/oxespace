# OXESpace 0.15.1

This patch release fixes project navigation between Thread and Code.

- Adding a folder already known to Thread now reuses its project context without changing the active Code workspace. A removed project can also be added back by choosing the same folder.
- Reusing an existing workspace no longer inserts its ID a second time in the Code sidebar.
- Removed Thread projects appear in a dedicated section and can be restored individually. Removing a project from Thread keeps its conversations, files and Code workspace.

Thread conversations still use a workspace context for persistence. Adding a new folder creates one single-pane compatibility workspace with terminal auto-start disabled.

Validation: focused Thread and workspace tests, SQLite integration tests, an Electron Playwright project-navigation scenario, typecheck, lint and the production build passed locally. The release workflow validates Windows and Linux packages before publication.
