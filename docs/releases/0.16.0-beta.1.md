# OXESpace 0.16.0-beta.1

This prerelease previews independent Thread projects and fixes conversation rendering in long sessions. It uses the beta update channel; the stable 0.15.2 channel remains available.

- Thread projects now have their own persistent registry. Adding, hiding, restoring or relinking a Thread project no longer creates or removes a Code workspace. **Open in Code** remains an explicit action.
- The database migration preserves conversations and their events when a Code workspace is removed. New Thread projects receive independent IDs; migrated projects keep their historical IDs.
- Thread project settings show their scope and delegation controls. Destination selection is explicit when delegating work.
- Long conversations now update their virtual window as the reader scrolls, preserve the reading position across view changes and load older history on demand. The project settings dialog also has compact, aligned controls.
- Worktree and new-Thread wireframes are included in `docs/plans/thread-independent-mode/`; the combined worktree creation flow shown there is a proposal, not a feature in this build.

**Beta limits:** the Thread runtime still carries a compatibility `workspaceId`; complete legacy task and preference migration, all four delegation directions, native `/resume` after migration and large-session migration are still open validation gates. See `docs/plans/thread-independent-mode/PLAN.md` before considering this separation complete.

Local verification covered typecheck, lint, build and bundle budgets, Thread unit tests, and Electron Playwright flows for project navigation, settings, long conversation scrolling and mode switching. The release workflow additionally gates publication on Windows and Linux CI, packaging and artifact verification.
