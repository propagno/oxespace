# OXESpace 0.17.0

Adds OxeQuery, a third mode for containers, PostgreSQL and MongoDB, and a set of
Thread improvements. Installs of 0.16.0 update automatically; the database is
backed up before the migrations run.

## Highlights

- **OxeQuery**, a third mode next to Code and Thread. See your containers
  (Docker or Podman) and work with PostgreSQL and MongoDB without leaving OXESpace.
  - **Containers:** state, ports, live CPU and memory, logs, start / stop / restart
    (with a confirmation for databases), run a command, open a shell; images,
    volumes and networks with sizes and a confirmed remove; a **New database**
    wizard that starts PostgreSQL or MongoDB and connects to it.
  - **PostgreSQL:** schema tree, SQL editor with schema-aware autocomplete, query
    tabs, saved queries and history, `EXPLAIN` / `EXPLAIN ANALYZE` as a plan tree,
    the failing token underlined with the server's hint, table / view / function
    definitions.
  - **MongoDB:** databases, collections, `find`, `aggregate`, inferred schema, indexes
    (create and drop), documents or table.
  - **Edit data safely:** stage row edits, insert and delete, review the exact SQL,
    apply in one transaction; a row that changed meanwhile is never overwritten.
    MongoDB documents are edited with the same conflict check.
  - **Export and import:** CSV, JSON, NDJSON and SQL; import with a column mapping, a
    dry run and an all-or-nothing transaction.
  - **Connect anywhere:** verified TLS (CA, client certificate), SSH tunnels with
    host-key pinning, MongoDB replica sets and `mongodb+srv`.
  - **For AI agents:** ten MCP tools behind a gateway. Off by default per
    connection; every data read and change is approved by you in a native dialog
    showing the exact statement; no writes to production; results are limited,
    masked and marked untrusted; an *Activity* tab keeps an append-only audit.
  - Read-only by default and enforced by the server; passwords live in the
    operating system's secure storage.
- **Thread** becomes a full workspace for agent work with Claude Code and Codex:
  - **Agent Work:** a conversation splits a job into tasks with dependencies that
    run in parallel worker conversations (`oxespace_work_plan`). Workers never get
    more access than their supervisor, tasks that edit files take turns, the
    supervisor hears back when a task fails, waits for input or the run ends, and a
    USD or turn budget stops every worker. `/work` shows runs and tasks.
  - **Review a turn change by change:** undo a single block, a file or the whole
    turn, send a block to the agent as a review comment, then **commit and open a
    pull request** with a message drafted from the conversation.
  - **Permission rules** answer approvals for commands, files and MCP tools
    (`/rules`), with *Always allow* on the prompt, high-risk commands that always
    ask, denied MCP tools removed before the session starts, and an audit trail.
    Claude can auto-accept edits inside the project.
  - **Spending:** every turn is recorded; `/spending` shows tokens and estimated cost
    by day, model and conversation. Codex turns now report tokens.
  - **Context:** a short project brief on the first message, `@`-mentioned files
    attached, `/instructions` lists the instruction files in effect, CodeGraph and
    semantic search work from a Thread, and a chip shows MCP servers that failed to
    start.
  - **Conversation:** Ctrl+F across the whole conversation, edit and resend, quote
    in reply, Esc stops the turn, failure cards with the right next step, and
    screen-reader announcements.
  - Also: per-message delivery state, a queue that pauses after a stop or a
    failure, context-window usage in the ring, a verified *Rewind to here* for Codex
    and Claude, a cooperative interrupt, running cost, quota alerts and keyboard
    navigation between conversations.

## Also in this release

- Faster startup: the Editor and Review panes and the OxeQuery mode load on
  demand. The preload bridge is minified.
- Incremental Thread reads (a cursor with an epoch) instead of rereading the
  whole window on every change.
- Database migrations 066–073 (a backup is taken before an upgrade as usual).
- `npm run verify:providers` checks the installed Claude Code and Codex for the
  protocol surface Thread uses, without sending a prompt.

## Security notes

- SQL that reaches outside the database even in a read-only transaction
  (`pg_read_file`, `lo_import`, `dblink`, `pg_terminate_backend`, `set_config`,
  advisory locks, `query_to_xml`…) is classified as a write, so it is refused on a
  read-only connection and by an agent's read tool.
- Claude with `bypassPermissions` and Codex with `approvalPolicy: never` do not ask
  before calling MCP tools; OxeQuery's own dialog is what protects a database.

## Known limits

- Podman support is implemented but has only been exercised through unit tests; the live suite runs against Docker.
- Several result sets from one multi-statement script show only the last one.
- A MongoDB dry run only validates the file; CSV values import as text.
- Rewinding to the first Claude message is not offered.
- Agent Work runs workers in the same working tree (no per-task worktree yet), and
  Teams and Delegation keep their own tools; their data is not moved into Agent Work.
- A denied MCP tool is removed from Codex only for servers OXESpace attaches;
  servers configured in Codex itself are governed by Codex.
- Codex turns record tokens but no cost estimate.
- Masking of agent results uses one built-in list of column and field names; a
  per-connection list is not available yet.
- The result grid has no "load more" for results beyond the row limit; raise the
  limit on the connection or export the result instead.
- The OxeQuery interface is English-only and, like the rest of the app, dark themes only.
