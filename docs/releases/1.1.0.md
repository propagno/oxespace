# OXESpace 1.1.0

Code and Thread now share the same panels, names and dialogs; idle conversations free their memory;
and Changes compares any two sides. Installs of 1.0.x on Windows update automatically; on Linux,
install the new package.

## New

- **Idle conversations free their memory.** A Thread conversation without activity for 15 minutes
  closes its agent process and the MCP servers it started; your next message resumes the same
  session. Choose never, 5, 15, 30 or 60 minutes in Settings › Agents › Idle conversations. A
  conversation keeps its process while a turn runs, a question waits, messages are queued, a
  background task runs, or a permission was allowed for the session only.
- **Start a conversation in its own worktree.** New thread can create a new branch in its own
  worktree; a worktree that conversations still use is not removed by accident.
- **Compare any two sides in Changes.** Pick a branch, ref or another worktree on each side, with a
  direct or common-ancestor comparison. Open a file from the editor, or a pull request from GitHub,
  straight in Changes.
- **The branch the agent really works on.** Code panes and Thread show the agent's actual working
  directory and branch, including worktrees it entered on its own.

## Improved

- **Panels in Code work like Thread.** The Tools window is gone. The workspace bar has Changes and
  Browser buttons and a Panels menu with Commit & pull request, Files, Find in files, Scripts and
  Worktrees; the rail's Panels button opens the same menu. Panels have the same names, icons and
  shortcuts in both modes (Ctrl+Shift+D Changes, Ctrl+Shift+B Browser, Ctrl+E Files, Ctrl+Shift+F
  Find in files). Team, Connections and Activity keep their buttons; Skills, the semantic index log
  and terminal commands are in the command palette (Ctrl+K).
- **One kind of dialog.** Every dialog has a title, a short description, a close button, Escape, and
  Cancel with one main action. Confirmations ask a question ("Archive this conversation?"), start
  on Cancel, and use a red button when they delete something or widen what an agent may do. The
  same question appears whether you use a slash command or the sidebar.
- **Real confirmations** instead of "click again" buttons or text inside a menu: deleting an agent
  profile, removing a worktree (with what would be lost), starting a new delegated session,
  cancelling a delegated task, trusting a new SSH host key, and enabling network access, "never
  ask" or provider hooks.
- **Menus, popovers and tool panels** (Connections, Skills, Scripts, Linear, Semantic activity,
  Browser) share one look and keyboard behavior: Escape and a click outside close them, and screen
  readers can still reach the rest of the app while a menu is open.
- Light theme: floating menus and popovers use the theme's shadows instead of fixed black ones.

## Fixed

- Settings has an **Agents** page again (agent CLIs, custom agents, idle conversations); it was only
  reachable from the first-run checklist.
- The Changes panel of a pane inside a worktree no longer shows whole files as deleted; the classic
  review is no longer zero pixels wide in the side panel; the branch pickers stay readable in a
  narrow panel.
- A Windows short path (`C:\Users\RUNNER~1\…`) and its long form are recognized as the same checkout.
- The workspace bar no longer turns into a scroll area that keyboard users cannot reach when it gets
  crowded.

## Known limits

The limits listed in [1.0.0](1.0.0.md) still apply.
