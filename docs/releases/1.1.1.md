# OXESpace 1.1.1

A hardening release for 1.1.0: security, conversation reliability and disk use. No new features.
Installs of 1.1.0 on Windows update automatically; on Linux, install the new package (the
AppImage updates itself).

## Security

- **The main window only shows OXESpace.** A dropped link, a link in agent output or a redirect can
  no longer replace the app with a remote page; web links open in your browser.
- **Stricter checks on requests from the window** that start processes, read microphone audio,
  send notifications or touch the MCP bridge: inputs are typed and bounded, and only the app's
  main frame may send them.
- **Unexpected errors in the background** are recorded in diagnostics, and OXESpace offers to
  restart instead of carrying on in an unknown state.

## Conversations

- **Two messages sent at the same moment** no longer start two turns; the second waits in the
  queue. A conversation never opens two agent processes at once.
- **Worktrees:** when the agent moves into a worktree during a turn, the turn's checkpoint and its
  verified changes are taken there too, so the turn can be reviewed and undone. A worktree path
  written in quotes is recognized.
- **Long messages:** a long queued message can be edited, and slash commands accept long text.
- **An unavailable default model** (for example one set in `~/.codex/config.toml` that your account
  cannot use) now says so and points to the model picker.

## Memory and disk

- Conversation histories are no longer all kept in memory; idle ones are read back when needed.
- **Startup is faster with many conversations:** only conversations a restart interrupted are read
  in full.
- **File checkpoints** (the copies that make a turn undoable) are kept for 30 days and at least the
  20 newest turns of each conversation; older ones are removed. Conversation text, tool results and
  costs are never removed.

## OxeQuery

- **A slow query no longer closes every connection.** Only that request fails and its statement is
  cancelled; the database worker restarts only if it stops responding.

## Known limits

The limits listed in [1.0.0](1.0.0.md) still apply.
