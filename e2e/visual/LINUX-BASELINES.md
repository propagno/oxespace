# Linux baselines for the visual suite

The visual suite compares screenshots against baselines stored per platform
(`__screenshots__/{platform}/...`). Windows baselines exist. Linux baselines have to be produced on
Linux, with Linux fonts, so they are generated by a CI job and reviewed before they are committed.

## Why a separate job

- Fonts rasterise differently on Linux, so Windows images cannot be reused.
- The runner image matters: baselines taken on `ubuntu-22.04` differ from `ubuntu-24.04`. The job
  uses `ubuntu-22.04`, the same image as the Linux leg of `ci.yml`. If the runner image changes,
  regenerate the baselines.
- It is `workflow_dispatch` only, so it never runs on a push and costs nothing until asked for.

## The workflow

Save as `.github/workflows/visual-baselines.yml` (a new file, so `ci.yml` is not touched). The action
versions are the same pinned commits `ci.yml` uses.

```yaml
name: Visual baselines (Linux)

# Generates e2e/visual/__screenshots__/linux for review. Never publishes anything and never
# commits: download the artifact, look at the images, then commit them by explicit path.

on:
  workflow_dispatch:
    inputs:
      branch:
        description: Optional override — leave empty to use "Use workflow from"
        required: false
        type: string

permissions:
  contents: read

jobs:
  linux-baselines:
    name: Generate and verify Linux visual baselines
    runs-on: ubuntu-22.04
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@93cb6efe18208431cddfb8368fd83d5badbf9bfd # v5.0.0
        with:
          ref: ${{ inputs.branch || github.ref }}
          fetch-depth: 0

      - name: Node.js 22
        uses: actions/setup-node@a0853c24544627f65ddf259abe73b1d18a591444 # v5.0.0
        with:
          node-version: "22"
          cache: npm

      - name: Linux system dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y --no-install-recommends \
            xvfb libnss3 libatk-bridge2.0-0 libgtk-3-0 libgbm1 libasound2 \
            libxshmfence1 libnotify4

      - name: Install dependencies without lifecycle scripts
        run: npm ci --ignore-scripts

      - name: Build
        run: npm run build

      - name: Prepare and verify native modules for Electron
        run: |
          npm run fix:native
          npm run verify:native

      # The first launch after a build was slower and failed transiently in local runs. A
      # throwaway pass warms it up; its result is ignored on purpose.
      - name: Warm-up (result ignored)
        continue-on-error: true
        run: bash scripts/run-with-xvfb.sh npx playwright test --config playwright.visual.config.ts anchor-surfaces

      - name: Generate the baselines
        run: bash scripts/run-with-xvfb.sh npx playwright test --config playwright.visual.config.ts --update-snapshots

      # Two consecutive comparisons against what was just written, with no rebuild between them.
      - name: Verify stable, run 1
        run: bash scripts/run-with-xvfb.sh npx playwright test --config playwright.visual.config.ts

      - name: Verify stable, run 2
        run: bash scripts/run-with-xvfb.sh npx playwright test --config playwright.visual.config.ts

      - name: Upload the Linux baselines
        if: success()
        uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4.6.2
        with:
          name: visual-baselines-linux
          if-no-files-found: error
          retention-days: 14
          path: e2e/visual/__screenshots__/linux/**

      - name: Upload the diffs when it is not stable
        if: failure()
        uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4.6.2
        with:
          name: visual-diffs-linux
          if-no-files-found: ignore
          retention-days: 7
          path: test-results/**
```

## Procedure

1. Run the workflow from the branch to be released (Actions, "Visual baselines (Linux)", Run workflow).
2. Download `visual-baselines-linux` and unzip it into `e2e/visual/__screenshots__/linux/`.
3. Open the images. They must show the intended screens, not blank windows, an error page or a
   missing font. Compare a few with their Windows counterparts.
4. Commit only that folder, by explicit path.
5. Once those files are committed, a visual job in `ci.yml` can run the suite without
   `--update-snapshots`.

## What this does not do

It does not run the suite on every push. That needs a normal job in `ci.yml`, which is a separate
decision: the suite is local-first for 1.0, and each CI visual run costs minutes on a runner.
